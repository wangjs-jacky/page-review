# 网页引用 404：根因、修复与验收

## 用户可见问题

在网页中点击「复制本页评注」得到`page-review-live-<64hex>`后，终端未能读取目标。旧Skill/CLI不识别外层前缀，随后人工执行又误用资料库最近记录代替目标。正确结果必须由原引用解析到原网页，不能以其他页面或按网址检索替代原引用验收。

## 根因证据

1. 线上实际部署模块读回确认没有live路由及live_pages逻辑。确定性计算确认用户原引用与当前授权空间、原目标网页相符；旧Worker把该编号交给固定清单查询并返回404，引用不是格式无效。
2. 扩展开发实现原先完全在本地计算引用，没有检查云端协议、必要schema或终端读取能力。因此即使云端还是旧版本也能显示复制成功。
3. 开发CLI虽已增加live前缀及--after处理，版本仍是公开0.4.3。官方安装器与公开包逐字节核对仍为旧实现，版本化资源带一年immutable缓存，重装同版本不能交付新行为。
4. 新live表只建空表，已有资料没有映射。即使更新Worker，reader直接读历史引用仍404，直到writer先浏览该页才被登记。
5. 旧终端没有读取协议回执；旧CLI会忽略未知--after，可能在最新保存尚未同步时读到旧资料。常规CI原先不执行真实workerd/D1/R2契约回归。

## 项目源码修复

- 独立工作树复用已有live协议草稿并保存原始patch摘要；原开发树没有被覆盖。
- CLI、安装器、Worker分发及构建共享版本合同：CLI0.4.4、读取协议1，使用新不可变资源路径，保留0.4.3等旧分发。
- 新增必要迁移检查、readProtocol/clientVersion终端回执。只有schema、全套发行资源和终端读取协议就绪，扩展才复制live引用。
- 旧资料缺映射时，仅在当前授权空间内单次读取至多501个页键；不超过500时匹配并登记原编号，超限明确要求回填。跨空间仍拒绝，不后台扫描。
- 新同步回执保留--after；未确认完整保存时返回409，不交付部分内容、不轮询。完整指令保留page-review-live外层前缀，让旧CLI明确拒绝而非忽略同步要求。
- 空页通过拥有者明确读取动作登记，可读零条，不创建业务评注；本地空但云端有历史时先单次刷新。
- Skill说明与安装包一起分发，明确失败不得猜页面；本机临时补丁不再作为项目交付。
- 扩展版本0.4.17，CLI独立0.4.4。精确固定Miniflare开发依赖，将两项真实运行时契约加入CI；另固定Bun1.4.5，在CI构建轻量CLI并解包校验版本、协议、SHA和真实读取行为。缺依赖明确失败，不能skip冒充通过。

- 空页复制与空页后端登记均先复现404，再验证零条完整读取、跨空间404及零业务写入。
